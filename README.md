# Storage Space

Файловый менеджер на Vue 3, FastAPI,
Python 3.14, SQLite, uv и Docker Compose. Зависимости backend заданы в
`backend/pyproject.toml` и закреплены в `backend/uv.lock`. Интерфейс использует
разметку, SVG-иконки и стили утверждённого прототипа. На S4 подключены
хранилища «Тест» (`storage/`) и «Просветление» (`/mnt/storagespace-prosvetlenie`).
Оба подключены в backend через bind mount; для SSHFS проверяется тип монтирования.
Backend работает с UID/GID `1000:1000`, владельцем тестового каталога на S4.
Операции приложения
идут через контракт `Storage` в `backend/storage.py`; сейчас реализован
адаптер `MountedStorage`. Позже можно добавить `SFTPStorage`, не меняя HTTP API
и Vue.

Загрузка идёт частями по 8 МиБ. Незавершённый файл лежит в скрытом каталоге
того же хранилища; сервер сообщает фактически записанное смещение. После
обрыва или перезагрузки страницы пользователь выбирает тот же файл, и передача
продолжается с сохранённого смещения. Скачивание и просмотр поддерживают HTTP
Range для возобновления и перемотки медиа. Браузер может потребовать повторно
выбрать файл после закрытия страницы. Загрузку можно отменить, чтобы удалить
незавершённый файл с хранилища.

Папку можно выбрать кнопкой «Выбрать папку» или перетащить в окно браузера.
Перед загрузкой интерфейс показывает число файлов, папок и общий объём; затем
создаёт дерево каталогов и добавляет файлы в обычную фоновую очередь. Уже
существующие файлы не перезаписываются и отмечаются как пропущенные. Браузерный
выбор папки передаёт только файлы, поэтому пустые вложенные папки через него
не появятся; при перетаскивании браузер может передать и пустые папки.
Крестик в заголовке панели загрузок запрашивает подтверждение и отменяет все
незавершённые файлы в очереди, удаляя их временные части. Завершённые файлы
и уже созданные папки остаются на хранилище.

## Установка как приложение

Сайт доступен как PWA на телефоне и компьютере. После входа пункт
«Установить приложение» находится в меню профиля. Если браузер поддерживает
системное приглашение к установке, оно откроется по нажатию; иначе интерфейс
покажет краткую инструкцию. На iPhone и iPad установка выполняется через меню
«Поделиться» в Safari и команду «На экран Домой». Установленное приложение
открывается в отдельном окне. Без сети показывается только экран состояния:
файлы и ответы API в браузере не кэшируются, для работы нужен сервер.

## Сведения о файлах

Завершённая загрузка через интерфейс получает постоянный UUIDv7. Файл,
появившийся в хранилище напрямую, получает ID при первом действии с ним:
просмотре, скачивании, открытии сведений или изменении. Открытие папки только
читает уже известные ID и не сверяет содержимое папки с SQLite.
SQLite хранит ID, хранилище, текущий путь, размер, время изменения, время
последнего обнаружения, статус и SHA-256. Папки пока не получают ID.
Перемещение и переименование через интерфейс сохраняют ID. Если при обращении
по ID файл не найден, запись помечается как отсутствующая;
повторное появление после обнаруженного отсутствия создаёт новый ID.

В меню файла пункт «Сведения» показывает ID и SHA-256. Расчёт хеша запускается
по кнопке и выполняется в фоне, по одному файлу за раз, без загрузки файла
целиком в память. Для изменившегося файла прежний хеш сбрасывается.
`POST /api/files/resolve`, `GET /api/files/{id}`, `GET /api/files/{id}/content` и
`POST /api/files/{id}/sha256` используют обычную проверку сессии и прав.
Публичных ссылок пока нет. Внешнюю замену файла с точно тем же размером и
временем изменения без полного пересчёта хеша обнаружить нельзя.

## Запуск

Скопируйте `.env.auth.example` в `.env.auth` и задайте реальные параметры Ark и
постоянный случайный `SESSION_SECRET` длиной не менее 32 символов. Этот файл
не должен попадать в Git. Для уже развернутого сервиса на S4 он подготовлен.

```sh
docker compose up -d --build
```

Приложение слушает только `127.0.0.1:50007` на хосте. Изменить порт можно через
`APP_PORT` в `.env`. Страница открывается через Caddy по адресу
`https://storagespace.example` (замените адресом своего домена).

## Релизы и запуск готовых образов

Релиз создаётся из чистой, актуальной ветки `main` командой:

```sh
./scripts/release.sh
```

Скрипт создаёт GitHub Release с UTC-датой в теге (`vYYYY.MM.DD`, при повторном
релизе в тот же день — `-patchN`) и ждёт завершения публикации двух образов:
`ghcr.io/planetic-labs/storagespace-backend:<тег>` и
`ghcr.io/planetic-labs/storagespace-frontend:<тег>`. Проверить следующий тег без
создания релиза можно командой `./scripts/release.sh --dry-run`.

Для запуска готовых образов скопируйте `.env.prod.example` в `.env.prod` и
укажите опубликованный `IMAGE_TAG`, путь SSHFS-монтирования и конфигурацию
хранилищ. Значения `id` и `path` в `STORAGES_JSON` должны соответствовать путям
в контейнере; при переходе с существующей установки сохраняйте прежние `id`,
чтобы записи в SQLite продолжили ссылаться на те же хранилища. Файл `.env.auth`
с действующими параметрами авторизации также должен находиться рядом с Compose.
Для PROD используется host-порт `50006`; DEV сохраняет `50007`.

```sh
docker compose --env-file .env.prod -f docker-compose.prod.yml pull
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d
```

Образы собираются для `linux/amd64` и привязаны к тегу релиза. Для скачивания
из GHCR может потребоваться авторизация Docker, если пакеты организации не
сделаны публичными.

## Пользователи и права

Вход через Ark Messenger: email и одноразовый код. В токене Ark должны быть
`sub`, `roles`, `status=active`, `exp`, `aud`, `iss`. Роли Ark сопоставляются
по текстовому имени с локальными ролями. Встроенный идентификатор `admin`
неизменяем; `warrior` и `student` можно переименовать в админке. У всех ролей,
групп и пользователей постоянные числовые ID. Разрешения ссылаются именно на
них, поэтому смена имени роли в Ark не меняет выданные права.

Администратор открывает управление через профиль внизу боковой панели.
Там можно создавать роли и группы, назначать участников, выдавать права
просмотра или изменения на всё хранилище либо на папку, отключать пользователя
и завершать его сессии. Права наследуются вниз; запретов для отдельных
подпапок нет. Пользователь видит только доступные ветки.

Сессии хранятся в SQLite, а браузер получает только непрозрачную cookie.
Локальное отключение пользователя или отзыв сессий вступает в силу на следующем
запросе. Изменения ролей в Ark проверяются при обновлении токена не реже чем
раз в 10 минут активной работы. При недоступности Ark после этого интервала
запросы временно блокируются. Ключ обновления Ark хранится в SQLite в
зашифрованном виде; `SESSION_SECRET` нужно сохранять при пересоздании контейнера.

## Эксплуатация

В админке есть вкладка «Журнал»: там видны время, пользователь, хранилище,
путь и тип завершённой операции. Записываются создание папки, завершённая
загрузка, отмена загрузки, перемещение и операции с корзиной. Просмотры,
поиск и скачивания в журнал не входят. Старые записи, сделанные до добавления
поля пользователя, показываются без имени; журнал хранится в той же SQLite.

Оба контейнера автоматически перезапускаются после сбоя и имеют проверки
работоспособности. Проверка backend проверяет доступ к SQLite, но не считает
отказ одного SSHFS-монтирования отказом всего сервиса: состояние каждого
хранилища отображается отдельно. Технические логи Docker ограничены тремя
файлами по 10 МБ на контейнер. `docker compose ps` показывает состояние
контейнеров; `docker compose logs --tail=100 backend frontend` — последние
технические сообщения. Проверка SSHFS на S4 описана в `deploy/systemd/README.md`.

Резервное копирование SQLite и конфигурации пока не настроено.

## Важно

Перед полноценной эксплуатацией с настоящими хранилищами нужны проверка
здоровья монтирования без
блокировки HTTP, защита от гонок при файловых операциях, очистка заброшенных
незавершённых загрузок и интеграционные испытания с обрывами SSHFS.

SFTP-клиент пока не реализован. В пилоте файлы отдаются через FastAPI;
перед эксплуатацией с большими файлами можно добавить прямую отдачу через
reverse proxy для SSHFS-адаптера.
